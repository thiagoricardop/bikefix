# Repair Content Guidelines

## Editorial principles
- Write for beginners with short, direct steps and define necessary technical terms.
- Identify applicable bicycle types and component systems. Ask for clarification when a difference changes the procedure.
- Keep source references with the guide and record revision/review status. Record access dates and specific scope/limitations for each reference.
- Source the procedure actually being described; a general article is not proof for a model-specific torque, limit, adjustment, or compatibility claim. Link to the exact bicycle/component manual when the system requires it.
- Use original, permissioned, or appropriately licensed photos, diagrams, animations, and video. Record provenance and usage terms. Do not hotlink media as a substitute for permission to reproduce it.
- Never present placeholder media as completed production content. Text-only guides are allowed when the media inventory explicitly says no media is attached and no rights claim is made.

## Mechanical accuracy
- Use manufacturer documentation and reputable technical references appropriate to the actual installed system. Manufacturer instructions for the exact bicycle and component take precedence.
- Do not invent torque values, specifications, compatibility claims, wear limits, or manufacturer-specific instructions.
- Distinguish draft content from mechanically reviewed content. A model, automated validator, author, or code reviewer does not constitute a qualified mechanic's review.
- Include prerequisites, expected observations, warnings, stop conditions, post-repair checks, and escalation criteria as appropriate.
- Avoid presenting a checklist as a guarantee of safety.
- Use inspection-only guidance and stop conditions when the source does not support a safe, broadly applicable repair procedure. Do not turn an unsupported procedure into a confident step list.

## Content lifecycle and reviewer record
1. Research and record reliable references, including title, publisher, URL, access date, and applicability notes.
2. Draft in the validated guide schema. Link source IDs, symptoms, components, bicycle types, and related diagnostic paths.
3. Run schema and cross-catalog validation; resolve every source/component/symptom/media reference error before requesting human review.
4. A qualified bicycle mechanic reviews the actual prose step by step, verifies system applicability, checks every warning/stop condition, and records actionable findings. Record the reviewer's name or approved identifier and the actual review date only after that review occurred.
5. Resolve findings and re-run validation. If the procedure is model-specific or the system is uncertain, narrow the compatibility statement or require the exact manufacturer's documentation.
6. Produce or source lawful media with alt text/captions/transcripts, attribution, rights status, and license data before attaching it. No asset is considered licensed merely because it is publicly viewable.
7. Mark a record `reviewed` only when an actual qualified human review and the required evidence are present. Mark it `published` only after editorial approval, resolvable source references, required media-rights evidence, and successful relevant verification. Keep drafts visibly unverified.
8. Revisit content when referenced specifications, component interfaces, source URLs, or known safety issues change.

### Minimum review record
For each review, capture: guide ID/version; reviewer name or organization; qualification/scope; date; source versions or access dates used; compatibility and tools checked; procedural findings; warning/stop-condition findings; media/rights review; changes requested; disposition; and the final revalidation result. Store only facts actually supplied by the reviewer. Do not manufacture placeholder approval records.
