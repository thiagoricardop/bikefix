# Security policy

BikeFix is an early-stage project. Security fixes and reports are handled by the repository maintainers.

## Reporting a vulnerability

Please do not publish credentials, personal information, repair-request records or an exploitable vulnerability in a public issue. Use GitHub's **Report a vulnerability** feature in the repository's Security tab when private vulnerability reporting is available. If that feature is not enabled, contact the repository owner privately before sharing technical details.

Include the affected version or commit, impact, reproduction steps and any safe proof-of-concept details. Do not access, alter or retain other people's data while investigating.

## Scope notes

- Never use real personal information when testing the local repair-request workflow; use synthetic data.
- Production request submissions must remain disabled until all documented deployment, storage, access, retention, rate-limit and notification controls have been verified.
- A passing CI workflow is not a penetration test or production security certification.
